Security hardening (#111):

- **Install for everyone on a computer, in Program Files (for IT).** `install.ps1 -Machine -Package <zip>`, run by Intune in System context, installs Unminute into `%ProgramFiles%\Unminute`, a folder only administrators can change, so the app's code is out of the user's reach. The installer gives the folder its own permissions and checks them, and those of every folder and file beneath it, at every run; it unpacks the package, and keeps the run's other temporary files, inside that folder rather than a temporary one, runs no Python, and refuses while anyone has the app open (exit code 3, so Intune retries). The Start menu entry for all users opens the current version through a fixed path, so pins keep working across updates, and the app then runs from that version's own folder. It keeps the current and previous versions and the newest version of the storage format immediately before the current one (and none in its place when that format is not installed), for users whose workspace still holds meetings in it, and installing an older storage format removes the newer one. It registers an uninstall entry for Intune detection and the Event Log source for the audit log. `uninstall.ps1 -Machine` removes it all again, and refuses while a version kept for an earlier storage format is installed unless `-IncludeKeptSlots` is given. Each user's workspace and models stay in their own profile, and no machine install, update or uninstall reads a profile.
- **A per-user install is refused once Unminute is installed for everyone (for IT).** The per-user installer stops with exit code 2 instead of adding a second copy beside the machine install.
- **The scripts stay unsigned.** Both modes run the installer scripts with `-ExecutionPolicy Bypass`, an accepted risk recorded in the security model.
