Security hardening (#111):

- **Graphics card components an update no longer uses are removed.** When an update of Unminute moves to a newer graphics card component, the copy that no installed version uses any more is removed by itself, a minute after start-up, freeing a few gigabytes. Nothing is removed while a download or check is running, while Unminute is also installed for the whole computer, or after updating from a version before this one, which does not say which components it uses.
- **Groundwork for the machine-wide install (for IT).** Where IT installs Unminute for the whole computer (a later version), each version is checked the first time it opens for a user, and a version that fails opens another kept version instead, with a message naming IT and a code. An update that changes how the workspace is stored runs a full self-test first and never migrates after a failed check. While a user's workspace still holds meetings, the version kept for it opens in finish-only mode, with a banner and at most one message a day: review, hand off and clean up, but no new recordings or imports. `--health` reports `slot`, `update_waiting` and `self_check`. Per-user installs start exactly as before.
