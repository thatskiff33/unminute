Security hardening (#111, slice B7b):
- **IT can block the app's runtime in Windows Firewall on a machine install.** `install.ps1 -Machine -Package <zip> -BlockRuntimeNetwork` adds two outbound block rules for each installed version, for its `runtime\python.exe` and `runtime\pythonw.exe`, in the group `Unminute runtime`. Later installs, rollbacks and removals keep the rules in step without the switch, a new version's rules are in place before it becomes current, and the machine uninstall removes them. It is off unless IT turns it on, and per-user installs never have it.
- **The firewall rule also blocks model downloads.** The download process runs the same program, so the rule is for computers where IT provides the models and sets `AllowModelDownloads` (or `AllowUserModels`) and `AllowGpuComponent` to 0. The installer warns while they are not set, and when Windows Firewall is off or ignores the computer's own rules for a network profile, where the rules do nothing (IT can deploy the same rules by Intune firewall policy instead).
- **The docs now say when the firewall rule applies.** Earlier notes, the security model and two code comments described "a firewall rule for managed devices" without its conditions: it applies only to machine installs where IT turned it on and Windows Firewall applies local rules, and it does not cover WebView2's shared processes. Released notes are left as they were.
