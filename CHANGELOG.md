# Changelog

Release notes for Unminute. The Release workflow reads the section
for the version being released, so keep one heading per version. From v0.5.0 the headings are
dated, `## vX.Y.Z (YYYY-MM-DD)`, and written by `tools/changelog.py`.

Changes not yet released are in [`changelog.d/`](changelog.d/README.md), one file per pull request.
`python tools/changelog.py vX.Y.Z` moves them into a new section here when a release is prepared.

## v0.5.0-preview.4 (2026-10-27)

Preview for testing, built by GitHub Actions with signed build provenance. Meeting content is now encrypted at rest (#111 phase C), which changes the storage format: an update from v0.5.0-preview.3 waits until the workspace has no meetings, holds, unfinished cleanup, recordings waiting to be imported or meeting audio files (the installer stops with exit code 5 and lists them), so finish and clean up first. Settings, watched folders, handoff templates, cleanup receipts, downloaded models and the saved Hugging Face token carry over. Earlier versions cannot open the new workspace. Not an update in place from 0.4.3 or earlier (see Updates in docs/PACKAGING.md).

- **Draft text while recording.** Turn on "Show draft text while recording" in Settings > Recording and speakers to see rough text of what is said, a few seconds behind, on the recording card. A stretch of talk with no pause shows in pieces of up to about 10 seconds, a length chosen after trials of 6, 8 and 10 seconds. It is made on this computer with Parakeet v2, kept in memory only, never saved, and replaced by the full transcript when you stop. Off by default; it pauses on battery unless processing on battery is allowed. Select Hide draft before sharing your screen (#104).
- **IT can turn off draft text while recording.** A new policy, `AllowLiveDrafts`, is in the administrative template. With it set to 0, draft text while recording cannot be turned on, and a draft in progress is stopped and cleared (#104).
- **New IT policy `AllowComputerAudioRecording`.** The ADMX template has a new value for recording the sound playing on the computer (such as the other side of a call) as a second track beside the microphone. Not set, it is allowed, and each person's switch stays off until they turn it on; 0 turns it off (#108).
- **Record calls: computer audio beside the microphone.** Settings > Recording and speakers (and Setup) has a new switch, **Also record computer audio**, off by default. With it on, Unminute also records the sound playing on the computer, such as the other side of a Teams or Zoom call, as a second track; the two are mixed into one recording at full level when you stop and transcribed once. It records every speaker and headset that is on or connected, so a call on a Bluetooth headset is caught too, and everything they play is recorded, including notification sounds, so turn on Do not disturb first. The question before each recording then names people on the call, and the recording card shows a thin Computer audio bar. Your organisation can turn it off (`AllowComputerAudioRecording`). The audit log's record of each recording's start says whether its notice named computer audio. See "Recording calls" in the user guide (#108).
- **Do not go back to an earlier version of Unminute while a recording with computer audio is unfinished.** Stop the recording and let it import first: an earlier version imports only the microphone track and then deletes the recording folder, so the computer track would be lost (#108).
- **Meetings play at a standard level.** Playback in a meeting is turned up or down to a standard listening level, so a quiet recording no longer needs the computer's volume turned right up. The saved recording is not changed (#108).
- **Your microphone and the call at similar levels.** In a recording with computer audio, the quieter of the two (usually your microphone) is brought up towards the other's level when the two are mixed, so playback no longer jumps between quiet and loud (#108).
- **Narrator no longer repeats itself.** The recording card's state ("Recording"), a meeting's banner and error line, and Setup's speaker model status were announced again at every update; each is now announced only when it changes (#346).
- **Copy and open ChatGPT.** The Hand off page's main button now copies the prompt and transcript, then opens chatgpt.com in your default browser. Sign in with your organisation's business account, paste, check and send: Unminute sends nothing and puts nothing from the meeting in the web address. Copy prompt and transcript, Copy prompt only and Save Markdown are still there, beneath it (#109).
- **IT can rename, re-point or turn off Copy and open.** New policy values `AllowHandoffAssistant`, `HandoffAssistantName` and `HandoffAssistantUrl` (in the ADMX template) set the button's name and a strictly checked `https://` address, for example for Copilot, or hide the button. A name or address set on its own, or one that is not valid, hides the button rather than falling back to ChatGPT, and Settings says so (#109).
- **Release accessibility evidence covers light and dark mode.** The release's evidence check now refuses an accessibility report unless it shows every view of the app window audited in both light and dark mode, as the release steps require. Nothing changes in the app itself.
- **Package layout.** The speech-engine and offline-guard modules now sit inside the app's `workspace` folder (`app\workspace\asr_engines.py` and `app\workspace\offline_guard.py`) instead of at the top of `app\`. Nothing changes in how the app works; IT tools that list or check the package's files by path see the new locations.
- **NVIDIA's cuDNN library is no longer in the package.** CTranslate2 bundles `cudnn64_9.dll` but its Windows build never uses it, so the package leaves it out. Whisper runs on the graphics card and on the processor as before, and one fewer NVIDIA library is redistributed (#176).
- **Licence texts for more bundled components.** The package has a new `licences/` folder with texts collected from each project's own release for components whose wheels ship none (FlatBuffers, primePy, proxy_tools) and for libraries bundled inside wheels (Intel OpenMP in PyTorch and CTranslate2, PortAudio, the WebView2 SDK, FFmpeg and the libraries PyAV bundles with it, and Zstandard in TorchCodec), plus CTranslate2 and Tokenizers, whose wheels ship none. `THIRD_PARTY_NOTICES.txt` names them and the DLLs each covers. A release build now stops if any bundled component or DLL has no licence text (#176).
- **Every bundled native library now has its licence text.** The Microsoft C++ runtime copies that numpy and pandas bundle are covered by the Microsoft conditions CPython ships with its Windows build, collected from CPython 3.14.8, so a release no longer stops on them (#176).
- **Monthly dependency update.** The bundled libraries move to their newest versions that have been public for at least 7 days, except those held back on purpose. Among them: PyAV 19.0.2 with FFmpeg 9.0.2 (was 17.1.0 with FFmpeg 8.1.1), which no longer crashes on a recording whose audio has no decoder and fixes a memory error with unusual channel layouts; CTranslate2 4.8.3 (fixes for Windows and Python 3.14); NumPy 2.5.4; pyannote.audio 4.0.7 with TorchCodec 0.17.0; and huggingface_hub 1.33.0 for model downloads. PyAV 19.0.2 was taken inside the 7-day wait as a security fix. Held back: ONNX Runtime 1.31, huggingface_hub 2, protobuf 7, OpenTelemetry 1.45, Optuna 5, multidict 7 and hf-xet 1.7 (#180, #310).
- **Security update: filelock 4.2.4** (was 3.29.1). It fixes three advisories (CVE-2026-112940, CVE-2026-112913 and CVE-2026-112907): another account on the same computer could interfere with filelock's SQLite-based reader and writer lock, or hold up a "soft" lock on Windows. filelock is used by the model download (huggingface_hub) to coordinate access to the model folder while files arrive; the speaker identification library only imports it, for a function Unminute never calls. Unminute's own code does not call it, none of its libraries uses the reader and writer lock, and the model folder is in your own profile, which other standard accounts cannot open, so exposure was nil in practice. setuptools also moves to 84.2.1 (was 84.0.0) for GHSA-xmj3-9gf7-h52w; it is removed from the package when it is built, so it never reaches your computer. Both updates were taken inside the usual 7-day wait for new versions, as a security exception. Nothing changes in how Unminute works.
- **Security update: Pillow 13.0.0 and certifi 2026.10.19** (were 12.3.0 and 2026.5.20). Pillow 13.0.0 fixes nine advisories in its TIFF, GIF, JPEG, EPS and PDF readers and writers and its image morphology module (CVE-2026-112395, CVE-2026-112397, CVE-2026-112400, CVE-2026-112403, CVE-2026-112404, CVE-2026-112895, CVE-2026-112896, CVE-2026-112897, CVE-2026-112899). Pillow is bundled only because matplotlib, which the speaker identification library depends on, needs it; Unminute never opens an image with it, so exposure was nil in practice. certifi 2026.10.19 removes the `emSign ECC Root CA - G3` root certificate from its bundle (PYSEC-2026-4320, GHSA-6q48-6c7w-9gw2). Model downloads check certificates against the Windows certificate store first and fall back to that bundle, so a site whose certificate chained to that root could still have been trusted; every downloaded file is still checked against its pinned SHA-256 before use. Both updates were taken inside the usual 7-day wait for new versions, as a security exception. Nothing changes in how Unminute works.
- **Recording with the window open uses less processor time on fast screens.** The recording display now redraws about 60 times a second rather than on every refresh of the screen: on every second refresh of a 120 Hz or 144 Hz screen, and on every refresh of a 60 Hz screen, as before. Its motion is now timed rather than counted in refreshes, so it moves at the speed seen on a 120 Hz screen whatever the screen: on 120 Hz screens it moves as before, and on 60 Hz screens it now eases about twice as quickly as before. Nothing else changes in how it looks (#216).
- **A data folder link whose folder cannot be reached now gets a message.** If `%LOCALAPPDATA%\Unminute`, or its `workspace` folder, is a junction or link to a folder that no longer exists or cannot be reached (for example on a drive that is not connected), Unminute closed at start without saying why. It now says the workspace folder is linked to a folder that cannot be reached and asks the user to contact IT, without naming a folder. `--status` gives the same message, `--health` reports `location`, and the installer's workspace check stops with exit code 6 and the same message. This includes a chain of links and a target written as a volume name or with the `\\?\` prefix, and nothing is created where the link points (#266).
- **A worker that ends no longer leaves its crash file open.** The background worker now closes its crash file before it ends, and the app waits for a stopped worker to finish ending (up to 30 seconds in all when the app closes on a busy computer, 5 seconds on Stop now), so the file is read and deleted as intended. A crash while a worker releases its model is now recorded too. Closing the app while a meeting was about to start processing can no longer leave a worker running.
- **Release performance figures are measured with the window actually on screen.** The release performance check now keeps the display on for its own run (the power plan is not changed), confirms for every visible state it measures that the display stayed on, the session was unlocked and the window was drawing, and stops rather than passing when it was not. The release notes' machine line now includes the display's refresh rate, since drawing cost rises with it. An earlier overnight run had most likely measured recording with the display asleep, which understated its processor use (#292). Nothing changes in the app itself.
- **The accessibility check lists the accepted exceptions for the brand look.** The brand border colour of fields, buttons and switches, and the meeting title without a border until the pointer is over it, are below the 3 to 1 that WCAG 2.2 asks of control boundaries (1.4.11). Both were accepted for the brand look on 25 October 2026, so the release accessibility check lists them as accepted exceptions and still fails on any other finding. The white tick on a done step's brand green is a graphic, which stands out 3 to 1 (#298).
- **The meeting title shows that it can be edited.** When the pointer is over the meeting title, which you can click to rename, a thin border in the text colour shows round it as well as the light background; with keyboard focus the thicker focus ring covers it. At rest the title shows no border, and fields, buttons and switches keep their brand border colour (#298).
- **A clearer "Optional", focus rings on pink, larger links to point at, and screen reader names that match the screen.** "Optional" on the current setup step is darker, so it stands out 4.5 to 1 (WCAG 2.2 1.4.3). On the pink of a hold notice, a search match or a passage left out of a hand off, the keyboard focus ring is dark instead of orange, so it stands out 3 to 1 (1.4.11). The back links, the passage times and text in a transcript, the hand off's template links and its "Replace names" box are each at least 24 pixels tall to point at, without moving anything (2.5.8). Playback speed, the speaker names dialog and the passages to leave out now have screen reader names that include the words on screen (2.5.3). The release accessibility check now says when its window lost keyboard focus during a view, or when the browser did not treat the focus as keyboard focus, instead of reporting every control there as having no focus ring (#298).
- **A stricter accessibility check before each release.** The release check of the app window now also tests target size, focus hidden behind other content, the contrast of focus rings and field borders, text spacing, keyboard traps, whether each control's accessible name matches the words on screen, image text alternatives, and the page language, title and status region, against WCAG 2.2 AA. It can check the window in light mode, dark mode or both (#298).
- **The release UI check no longer depends on its window having focus.** When the check's window was behind another, ending a transcript edit sent the page no blur event, so the edit stayed open and the growing-transcript step could fail on an unchanged app. The check now ends the edit as a focused window would, and records whether the window had focus in the steps that depend on it (#308). Nothing changes in the app itself.
- **The key and database check states are kept when a file is busy.** When another program, such as an antivirus scan, held `logs\keys.json` or `logs\integrity.json` open for a moment, Unminute could skip recording the state, so `--status` and `--health` showed the previous one. It now tries again for up to about 0.8 seconds, and a write that still fails is noted in the diagnostics log (which file only, no content).
- **The release accessibility check can now audit light and dark mode whatever mode Windows is in.** With Windows in dark mode, a light-mode run stopped before auditing anything, because the check did not really switch its window's page. It now switches the page of its own window only, never Windows' setting, and still checks that the page shows the mode before auditing it (#328). Nothing changes in the app itself.
- **The window opens sooner.** Unminute now loads the parts its window needs (.NET and the WebView2 control) in the background while the rest of the app starts, instead of after it, so the meeting list appears about a quarter of a second sooner in measurements on the development laptop. Nothing changes in what the window does or how it is secured (#339).
- **The automatic UI check now covers the Meetings page while recording.** Every pull request now counts what the page does with a recording going, visible and minimised: how often it asks the app for the clock and level, its timers, and how often the level meter draws on a simulated 120 Hz display. It fails if the meter draws other than about 60 times a second while visible, draws at all while minimised, polls while minimised, or rebuilds the meeting list while recording (#340, #348). Nothing changes in the app itself.
- **Queue model downloads.** In Settings > Manage downloads and in Setup, Download on another model while one is downloading now queues it instead of refusing. Each queued model shows Queued, its place and Cancel, and they download one at a time, in the order you chose. If Unminute closes with downloads queued, they carry on the next time it opens. Policy that turns downloads off empties the queue.
- **A microphone connected while Unminute is open now appears in the list.** The Meetings page's microphone list and Setup's list ask Windows again when you open or click into them, when you come back to the page and when a recording ends, so a headset plugged in later no longer needs a restart. If the microphone you chose is disconnected, Unminute says so and selects the Windows default; nothing starts. The list is never refreshed while recording (#369).
- **Draft text goes from the screen when drafts stop mid-recording.** When your organisation turns draft text off, or a speech model download or removal stops it, during a recording, the draft text already shown is now cleared, as the app had already cleared it from memory. Before, the recording card kept showing it and asked the app for it again about ten times a second until the recording ended. The recording itself was never affected (#370).
- **The release UI and accessibility checks cover draft text.** Both checks now include a recording with draft text, made from invented sentences with no microphone or speech model: Hide draft and Show draft, the box following the newest line unless scrolled up, the note for each state, a minimised window fetching nothing, and the draft area's screen-reader, keyboard and contrast points in light and dark (#370).
- **The release accessibility check waits for the page to settle.** Before measuring each view it waits up to 3 seconds for animations and transitions to finish, so a colour caught mid-change (such as a Settings switch just after the light or dark switch) is no longer reported, or excused, wrongly. A view that has not settled by then fails the check (#370).
- **The recording card fits a narrow window.** In a window about 320 pixels wide, or at 400% zoom, its buttons now wrap onto a second line instead of running past the card edge, which hid part of Discard and made the page scroll sideways. Nothing changes in a normal-width window (#370).
- **Draft text from both tracks uses bounded memory.** With computer audio on and the draft following both tracks, the computer audio waiting for draft text is capped at 60 seconds while draft text gets ready or catches up, whatever the audio devices' rates. At the computer audio's usual 48 kHz the live mix holds at most about 6.3 MB of computer audio in Unminute; the draft process holds at most about 1.9 MB with a 48 kHz microphone, up to 7.7 MB at 192 kHz (computed, not measured). If draft text is held up for more than 60 seconds, that first minute is still drafted from both tracks, and the audio after it is not drafted, as already happens with the microphone alone. The saved recording is never affected (#371).
- **Draft text that cannot start says so.** When the draft worker fails to start, the recording card now says draft text stopped, instead of saying a speech model was downloaded or removed. The recording is not affected (#381).
- **The draft note keeps saying why draft text ended.** When draft text is ended for the rest of a recording (its speech model is not ready, a speech model is downloaded or removed, or it cannot start), a later change to battery power or to your organisation's settings no longer replaces that line with a "paused" or "turned off" note that then stayed after the change. The recording is not affected (#384).

Security hardening (#111):

- **Unminute opens your workspace in only one Windows session at a time.** If you are signed in to Windows more than once (for example at the computer and by remote desktop), a second copy of Unminute could open the same workspace beside the first. It now says "Unminute is already open in another Windows session of yours. Close it there first." and opens nothing, so two copies never change your meetings at once and a storage update never runs while the workspace is open elsewhere.
- **The install record lists each kept version's storage format (for IT).** `current.json` now records, for each version the installer keeps, the workspace storage format it uses and the order it was installed in, and `-Rollback` keeps that record. The package's `version.json` states its storage format. This prepares the machine-wide install, where each user's own start decides which installed version opens their workspace. Per-user installs update exactly as before.
- **Graphics card components an update no longer uses are removed.** When an update of Unminute moves to a newer graphics card component, the copy that no installed version uses any more is removed by itself, a minute after start-up, freeing a few gigabytes. Nothing is removed while a download or check is running, while Unminute is also installed for the whole computer, or after updating from a version before this one, which does not say which components it uses.
- **Each version is checked the first time it opens.** After an install, an update or a repair, the first start takes a few seconds longer while the version checks that it can run on this computer: its modules and WebView2 load, the network guard holds and Windows can protect a key for you. On a new Windows profile the second start is checked too. A check that is slow while antivirus software scans the new files is run once more before it counts as failed, so a version that does not answer at all holds the start for about a minute before its message shows. If the version itself fails, the previous version opens instead when it uses the same workspace format, with a message naming IT and a code; otherwise the message shows and nothing opens. Repairing or reinstalling the version lets it be checked again.
- **Each person's start under the machine-wide install (for IT).** Where IT installs Unminute for the whole computer (`install.ps1 -Machine`, new in this release), each version is checked the first time it opens for a user, and a version that fails opens another kept version instead, with a message naming IT and a code. An update that changes how the workspace is stored runs a full self-test first and never migrates after a failed check. Like the worker processes, the self-test removes `HIP_PATH` before Whisper's libraries load (#357). While a user's workspace still holds meetings, the version kept for it opens in finish-only mode, with a banner and at most one message a day: review, hand off and clean up, but no new recordings or imports. `--health` reports `slot`, `update_waiting` and `self_check`.
- **The installer checks the copy it installs, file by file, by exact name.** It now copies the package into the install folder first and checks that copy against the package's manifest, so the files checked are the files that run. A file whose name differs from the listed one only in letter case, or by a look-alike character, counts as an extra file and stops the install, as does a link or junction anywhere in the package. The workspace check before an update runs from that checked copy, never from the temporary folder. A copy that fails is removed and nothing else changes.
- **One install at a time, and an install record that is never half-written (for IT).** A second install, update or rollback of the same folder waits for up to 10 minutes for the first, then stops with exit code 1; the uninstaller stops with exit code 3 while an install runs. `current.json` is written to a temporary file and then replaces the old one in one step.
- **An installer log (for IT).** Each install and rollback adds a line per step to `logs\install.log` in the install folder: the time, version, step, result and exit code, with no user name, path or message text. It keeps one earlier file once it reaches 256 KB.
- **The uninstaller checks what kind each of its entries is.** A folder where the installer puts a file, such as `current.json`, or a file named `versions`, now stops the uninstall before anything is removed (exit code 1).
- **Install for everyone on a computer, in Program Files (for IT).** `install.ps1 -Machine -Package <zip>`, run by Intune in System context, installs Unminute into `%ProgramFiles%\Unminute`, a folder only administrators can change, so the app's code is out of the user's reach. The installer gives the folder its own permissions and checks them, and those of every folder and file beneath it, at every run; it unpacks the package, and keeps the run's other temporary files, inside that folder rather than a temporary one, runs no Python, and refuses while anyone has the app open (exit code 3, so Intune retries). The Start menu entry for all users opens the current version through a fixed path, so pins keep working across updates, and the app then runs from that version's own folder. It keeps the current and previous versions and the newest version of the storage format immediately before the current one (and none in its place when that format is not installed), for users whose workspace still holds meetings in it, and installing an older storage format removes the newer one. It registers an uninstall entry for Intune detection and the Event Log source for the audit log. `uninstall.ps1 -Machine` removes it all again, and refuses while a version kept for an earlier storage format is installed unless `-IncludeKeptSlots` is given. Each user's workspace and models stay in their own profile, and no machine install, update or uninstall reads a profile.
- **A per-user install is refused once Unminute is installed for everyone (for IT).** The per-user installer stops with exit code 2 instead of adding a second copy beside the machine install.
- **The scripts stay unsigned.** Both modes run the installer scripts with `-ExecutionPolicy Bypass`, an accepted risk recorded in the security model.
- **The installer only removes what it installed.** An update used to remove every folder in the install folder's `versions` folder except the current and previous versions, so an `-InstallDir` that already held an unrelated `versions` folder (a shared folder or a drive's root) could lose its contents. The installer now refuses, with exit code 2 and before writing anything, an install folder that is not new, empty or an Unminute install, or that holds a link or junction where it would look; an install that stopped before it finished can still be completed by running it again. It removes only version folders it made, never through a link, and leaves anything else in place. A `current.json` makes the folder an install only when it is a JSON object that names a valid version and, if it gives a path, this folder's own version folder, so another program's file of that name does not. The uninstaller, too, never removes through a link or junction: it stops if one is at its own entries, and removes one inside a version as a link. The package's version and the values in `current.json` must be plain version names before they are used as folder names, so a damaged or altered value cannot lead outside the install folder; `-Rollback` refuses one (#297).
- **IT guidance on stopping per-user copies.** The IT deployment guide now explains how IT can use AppLocker or App Control for Business to stop Unminute's per-user installer and per-user copies running on managed computers, while allowing the planned machine-wide install in Program Files. It covers which folders and rule types to use, why hash and publisher rules cannot tell the two copies apart, what the rules break (every install until the machine-wide install ships, and the GPU components) and their limits. Each rule cites Microsoft's documentation and is marked "to confirm": none has been tested on a managed computer yet (#304).
- **Whisper no longer looks for libraries in a folder named by `HIP_PATH`.** CTranslate2, which runs Whisper, adds `%HIP_PATH%\bin` to the places Windows looks for libraries when that variable is set. Unminute's worker processes now remove it before Whisper loads, so a library placed in that folder cannot load into them, on the graphics card or the processor. Nothing else changes for users (#357).

Security hardening (#111, phase B):

- **For IT: offboarding a person who leaves.** Run as the user, `runtime\python.exe -I -B -X disable-remote-debug -m workspace --offboard-report` lists, as counts and yes or no only, what Unminute keeps for them, and `--offboard` removes it with the app closed: the workspace with its logs and audit log, the downloaded models and the remembered Hugging Face token. It removes nothing while a meeting, retention hold, unfinished cleanup, recording or meeting audio is left, so meeting content is still only deleted through the app's own confirmed steps. It puts the lid setting back, records an `offboarded` entry in the audit log and the Windows event log, and erases the workspace's key before deleting anything, so a removal that stops part-way leaves nothing that can be opened; running it again finishes the job. Anything else in the data folder, such as a workspace set aside after damage, is left alone and counted, and the command then ends with exit code 4 rather than reporting a clean removal. It does not look at anything version 0.4.3 or earlier left. It refuses to run as Local System, while the app is open, or when the data folder is a link to somewhere else. A plain uninstall still keeps the data. See `docs/IT_DEPLOYMENT.md`, "Offboarding".
- **For IT: offboarding and uninstalling in one step.** Run as the person who leaves, `uninstall.ps1 -Offboard` (with `-Silent` for Intune) first removes what Unminute keeps for them, as `--offboard` does, and only then removes the program, its Start menu shortcut, its taskbar and Start pins and its uninstall entry. If anything stops offboarding, such as a meeting, retention hold or unfinished cleanup still left, or the app still open, the uninstall stops too, says why with counts only, and keeps the program so the person can finish with it; running it again finishes the job. Other items left in Unminute's data folder, such as a workspace set aside after damage, are reported with their count and left for IT to check, and the uninstall carries on. It never runs as Local System, refuses an install folder that is not the running account's own (its uninstall entry's, or one in its own local app data folder), and starts nothing when it refuses. Without `-Silent` it shows what will go and asks the person to type REMOVE. Pins to other programs are kept. See `docs/IT_DEPLOYMENT.md`, "Offboarding".

Security hardening (#111, phase C):

- **Meeting content in the workspace database is encrypted.** Titles, notes, passages, word timings, edits and their history, speaker names, redaction words, hold reasons, source and watched-folder paths are sealed with AES-256-GCM under keys that Windows protects for your account on this computer, and hashes of recordings are kept as keyed fingerprints. An empty workspace from an earlier version is converted when the app first opens it, keeping its settings, watched folders and receipts; the installer waits while a workspace still holds meetings, as for any storage change. The app's working copy of the audio is encrypted too (see below).
- **A key Windows will not unlock stops the app with a message and a code.** Your meetings are kept and never shown or stored unencrypted. The user guide's "If Unminute cannot unlock its workspace" has the steps for IT; `--status` and the installer's check still work. `--self-test` also checks that Windows can protect and unlock a key.
- **A damaged part of a meeting shows as "[Could not be read]".** The meeting can still be discarded or finished, but nothing is made from it: no handoff, review confirmation, edit or name change.
- **Watched folders are compared without regard to case.** `C:\Rec`, `c:\rec\` and a junction to it are the same folder; a folder listed twice is merged into one with the lesser of its settings, and its note says so.
- **Handoff templates are encrypted.** Your edited and custom templates are kept in `templates.sealed`, sealed with AES-256-GCM under the workspace's key, which Windows protects for your account on this computer. A `templates.json` from an earlier version is converted the first time you use templates, keeping its titles, prompts and versions, and is then deleted; a damaged one gives no saved templates, as before. If it cannot be read at that moment, it is kept as it is and tried again the next time you start Unminute; one that is unusually large (over 8 MB) is kept as it is and not converted, and IT can help. Until it is converted, the built-in templates are shown and templates cannot be edited or added. An encrypted templates file that is damaged leaves the built-in templates until you save one; one that cannot be read at that moment is kept, templates cannot be edited until you restart Unminute, and nothing is lost.
- **Meeting audio is now encrypted on this computer.** The app's working copy of each meeting's audio is encrypted with AES-256-GCM under that meeting's own key, which Windows protects for your account, and no unencrypted copy is written. It is checked in full once when it is imported; a part that has been damaged or changed stops transcription, keeps the transcript so far and says so, and playback says the audio could not be read. Speaker identification on such audio fails on its own and leaves a finished transcript ready for review. Speaker identification receives the meeting's key only for its own pass. Microphone recordings are encrypted as they are saved too (see below).
- **The installer's update check names IT's next step for leftover audio.** A meeting audio folder that belongs to no meeting, which the app never removes by itself, still makes a storage update wait; the reason now says IT can delete it once nothing requires keeping it.
- **Microphone recordings are now encrypted as they are saved.** Each few seconds of a recording is saved encrypted under that recording's own key, which Windows protects for your account, and no unencrypted copy is written at any point: the recording goes to the sandboxed decoder from memory, with no `recording.wav`. Once the recording has become a meeting ready to transcribe, or when you discard or delete it, its key is deleted before the saved files, so anything left on disk cannot be read. If setting up the meeting fails, the recording and its key are kept so you can choose Try again. A piece that has been damaged is left out as silence and reported, and a recording whose saved audio cannot be read at all is kept for you to delete, never removed on its own. The recording's details and your recording confirmation are kept, encrypted, with the meeting until its audio is removed.
- **Removing a meeting's audio makes it unreadable first.** When you confirm the transcript review (or discard a meeting), Unminute now deletes the audio's key and clears it from the database's log before it deletes any audio file. If the app stops part way, or another program is holding a file, whatever is left can no longer be read, and the meeting shows its audio as removed while the leftover files are deleted on the next try. An import that fails also deletes its keys before its files.
- **Unminute opens locked when Windows will not unlock its key.** If Windows cannot unlock the workspace's encryption key for your account (for example after IT resets your password, or your profile is damaged), Unminute now opens locked instead of closing. It reads none of your meetings, changes none of your meetings or settings (it only records the problem in its logs) and never shows anything unencrypted; processing, imports, recording and cleanup wait, and anything that would read or change your meetings is refused. Help > Copy diagnostics still works, and now names the key's state with the Windows error number and a code, the number of active holds and the number of meetings whose cleanup was confirmed but not finished. Close Unminute, sign out and back in, then open it again: if Windows can unlock the key, everything carries on. For IT, `--status` shows `keys`, `lock_reason` and `lock_code`, and `--health` reports `locked`, both from what the app recorded at its last start, without trying the key. If Windows cannot set up a key for a new workspace, Unminute says so with the Windows error number and a code.
- **A locked screen when Windows will not unlock Unminute's key.** Instead of the usual window, Unminute now shows only a screen headed "Unminute is locked". It says in two short sentences what happened and that nothing has been deleted, shows the codes your IT team needs (with the Windows error number), and has three buttons: Copy details for IT, How to recover and Close Unminute. It shows no meeting and asks for nothing else in the background. What to do (sign out of Windows and back in, then copy the details for IT) is in How to recover; IT's steps (rename the workspace folder, keep it while any hold applies) are on the screen and in the user guide.
- **A content-free audit log of how meetings are handled.** Unminute now records when each meeting is imported or recorded (with the recording confirmation), reviewed, handed off (copied, saved or opened in the assistant), held, cleaned up or discarded, and when watched folders and permission to delete originals change. Each entry holds the kind of action, the time, the app's own reference numbers and counts only: never titles, names, text, file or folder names, or hold reasons. The log is kept in `workspace\audit\`, at most 16 MB, and each entry carries a fingerprint of the one before, so an edited, reordered or removed entry shows, except entries removed from the very end, which only the event log copy shows. The user guide has a short section, "What Unminute records about your work".
- **For IT: a copy in the Windows event log.** A fingerprint of each entry (not its reference numbers) is written to the Windows Application log under the source `Unminute`, with the user's Windows account. Forwarding that log off the device makes it the stronger record. `runtime\python.exe -I -B -m workspace --verify-audit` (as the signed-in user) checks the chain, and with `--event-log` or `--event-log-file` compares it with the event log copy. `--status` adds `audit_seq`. See `docs/PACKAGING.md`.
- **Meetings left waiting show "Review due", and "Action required" if your organisation sets it.** A meeting whose next step (review, hand off, or confirm or finish a cleanup) has waited 30 days or more gets a "Review due" label on the Meetings page and moves to the top of its group, with a banner, while the app is open. IT can change the number of days or turn it off (`ReviewReminderDays`), and can turn on "Action required" (`ActionRequiredDays`), which lists those meetings first. Each step counts from when it began. Nothing is blocked or deleted, and a hold that stops a step's cleanup also stops its label. This replaces the earlier rule that ordinary unfinished work got no reminders.
- **IT can see the backlog without seeing content.** `--status` adds `reminders_due`, `action_required` and `held_overdue` counts, and `--health` adds `action_required` and `held_overdue` without changing `healthy`. Run the remediation with the logged-on credentials: run as SYSTEM it counts nothing. Copy diagnostics shows the thresholds in force, whether IT set them, and the counts.

Security hardening (#111, D2 red team):

- **Recordings are decoded with audio decoders only.** Opening a recording no longer runs a video, image or subtitle decoder on a video track, cover art or subtitles, so a crafted picture or video track cannot reach those decoders. Audio in video files, MP3s with cover art and FLAC files with a picture still import, and so do phone and VoIP speech recordings (G.729, G.723.1, GSM, iLBC and Speex).
- **Small files can no longer decode to hours of audio.** A recording with a sample rate below 4 kHz or above 384 kHz is refused, and so is one that would decode to more than one second of audio per 16 bytes of file. Before, an 86 KB file could fill 2.5 GB of disk and queue 12 hours of transcription.
- **A damaged WAV header no longer crashes the decoder.** A file with no usable audio decoder (for example 0 bits per sample) is refused as unsupported or damaged.
- **The security model no longer says the firewall rule stops a compromised decoder sending data out.** That rule (B7) is not shipped yet; a stricter decoder sandbox is tracked in #299.
- **A very long path no longer stops a watched folder.** Without long paths turned on, Windows cannot open a file whose full path is 260 characters or longer. One such path inside a watched folder used to stop the folder's first check from finishing, so nothing was ever imported from it. Now those recordings are counted in the folder's note ("move them to a folder with a shorter path") and the rest of the folder is imported as usual. Importing such a file by hand says its path is too long, rather than that it could not be found.
- **Very broad folders can no longer be watched.** As well as a whole drive, your user folder and the Windows and program folders, Unminute now refuses the folder that holds every user's profile (such as `C:\Users`), any folder in `AppData` (such as `Temp` or another app's data folder), and Unminute's own data folder or any folder that holds it. A folder like this that you watched with an earlier version is no longer checked, and its note says why.
- **Policy folder paths expand like Windows.** A `HandoffDefaultFolder` set as an expandable string expands only `%NAME%` variables, as Windows does; `$NAME` is left as written.
- **Mistyped policy names are recorded.** A policy value whose name Unminute does not recognise (for example with a trailing space or a lookalike letter) still grants and withholds nothing, but the app now keeps the first 20 such names, and Copy diagnostics says how many there are.
- **Titles and speaker names drop invisible format characters.** A right-to-left override or similar character in a file name, a rename or a speaker name is removed, so a title cannot disguise itself in the meeting list. The joiners that Persian and Indic scripts need for correct spelling are kept.
- **Downloads use the standard HTTPS port only, and graphics card component redirects are checked more strictly.** A download address on another port is refused, and a redirect for a graphics card component is compared by its decoded path, so `..` or an encoded `..` cannot step outside the pinned location.
- **Settings names mistyped policy values.** When your organisation's policy has a value whose name Unminute does not recognise (for example with a trailing space, shown as `\x20`), Settings lists the names near the top of the page and asks you to have your IT team check them. Such a value still turns nothing on or off (#300).

- **A retention hold now also protects an import that never finished.** At start-up, such a meeting used to be removed even if it had a hold. It now stays listed as **Import did not finish**, and Discard removes it once the hold is released (#193).
- **Removing a meeting on a damaged workspace finishes.** After **Continue anyway**, removing a meeting deletes its text and audio, and the receipt says the database compaction is deferred until the workspace is repaired. The cleanup is no longer retried for ever (#198).
- **Meeting folders are checked before use.** The app builds a meeting's folder path only from its own ids, so a damaged database can never point a removal outside the app's media folder (#194).
- **A recording with several channels no longer loses a track.** Every channel is now mixed in equally. Before, a file with 3 or more channels, for example from a multitrack recorder that gives each person a track, could lose a whole track (for example the third of three, or the fourth of six to eight), and other tracks were halved or mixed louder than full scale. Stereo recordings are now 3 dB quieter, with nothing else changed, and mono recordings are unchanged. Some files with an unusual channel layout that could not be imported before now import (#220).

Security hardening (#111, slice A2):

- **Settings are checked when the app starts.** A value in `settings.json` that the app would not accept from Settings (for example an unknown speech model) is replaced by its default.
- **The window refuses to open unsafely.** The app now stops with a message if Windows would fall back to the old Internet Explorer engine instead of WebView2, or if its window protections cannot be put in place.
- **Tighter limits on what the page can ask for.** The page can show only the app's own screen, drag and drop accepts only files Windows reports as dropped, and calls with the wrong arguments are refused before they run.
- **Less left behind.** The window's browser data is kept inside the workspace folder and cleared at the next start if the app did not close cleanly, and SQLite keeps its temporary data in memory rather than in the Windows temp folder.
- **The handoff file name no longer contains the meeting title.** Save suggests `Meeting transcript YYYY-MM-DD HH-MM.md` (when the meeting was imported), so client names in titles do not end up in file names by default.
- **A Hugging Face token left in your Windows environment is no longer passed on** to the app's other processes.
- **The app refuses a missing, synced or network app data folder** instead of falling back to the current folder.
- **Only one copy runs at a time.** Opening Unminute again while it is open shows a message instead of starting a second copy on the same workspace.

Security hardening (#111, slice A3):

- **Recordings are decoded in a separate, sandboxed process.** Each imported file is decoded by a short-lived helper that runs at Windows' Low integrity level (the level browsers use for web pages) inside a Windows job. Windows stops it writing your files, opening the app's process, starting programs directly or using more than 2 GB of memory, and normally also the clipboard (inside some managed sessions the session's own limits apply instead), and it ends when the app closes. It sends back only plain audio, which the app checks, writes and hashes itself. It can still read files you can read, so a decoder flaw would mainly be a privacy risk; the firewall rule for managed devices (#111 B7) closes the network side.
- **Only real recordings are opened.** The decoder accepts only the supported recording formats and local files, whatever a file claims to be, so playlists, stream descriptions and scripts disguised as recordings are refused.
- **Limits on what a file can do.** Decoding stops at 12 hours of audio and keeps at least 1 GB of disk space free.
- **Network drives are refused for imports.** Files on mapped network drives, or reached through a symbolic link, are refused with a message to copy them first. Synced folders such as OneDrive are unaffected.

Security hardening (#111, slice A4):

- **The network block covers more.** Besides ordinary connections and name lookups, the app's Python processes now also refuse UDP datagrams and the Windows asyncio connection path, which went around the block before. `--self-test` checks all three against a reserved address that is never contacted.
- **Downloads can reach only their own sites.** The download process may contact only huggingface.co and hf.co (models), download-r2.pytorch.org (the optional graphics card component) and any proxy configured for you. Every request and every redirect is checked, also when downloads go through a proxy, and anything else is stopped with its own message. Hugging Face's native Xet downloader is switched off so every download goes through these checks.
- **Downloads work behind a firm's inspecting proxy.** Certificates are checked against the Windows certificate store (truststore), so a proxy certificate that IT has installed is trusted without any unsafe workaround. A fixed proxy is needed: proxies given only by an automatic configuration script (PAC or WPAD) are not used.
- **The speaker model is fully checked before every use.** Its files are re-hashed each time they are loaded, not just compared by size and date, because the model format can run code.

Security hardening (#111, slice A5):

- **IT can manage the app's settings.** On managed computers the app reads policy values from `HKLM\SOFTWARE\Policies\Unminute` (at start and every 15 minutes), which standard users cannot change. IT can turn off model downloads, the graphics card component, microphone recording, watched folders and deleting originals; allow recordings on mapped network drives; set a starting folder for saved handoffs; allow the meeting title in handoff file names; and have the app clear its handoff copy from the clipboard after a set time. An administrative template for Intune is in `packaging/policy/`.
- **A bad policy value never grants a permission.** A value of the wrong type or out of range turns that permission off rather than on, and a policy key that cannot be read turns every permission off.
- **Settings shows what is managed.** A note at the top of Settings says some settings are managed by your organisation, and managed controls are disabled. Setup and Downloads show "Ask your IT team" instead of a Download button where downloads are off, or "Turned off by your organisation" for the graphics card component. The app enforces each value itself, whatever the page shows: for example, a recording in progress is stopped and saved when microphone recording is turned off.
- **Without a policy the app behaves as before.**

Security hardening (#111, slice A6):

- **Each recording starts with a confirmation that everyone has been told.** Before recording, Unminute asks you to tick that everyone in the meeting has been told it is being recorded, and why, then select Start recording. The question is drawn by the app outside its page, so nothing in the page can answer it: Start recording becomes available after a moment; keyboard and screen-reader users move to it and pause briefly before pressing Enter, and Enter anywhere else means Cancel. IT can turn it off with the new `RequireRecordingConsent` policy.
- **You can see when the app is recording.** The window title starts with a red-dot "Recording" mark and the app's taskbar button shows a red dot, also when the window is minimised.
- **Discarding a meeting and allowing the app to delete originals use the same protected confirmation**, in place of the page's own dialog. The deletion question names the folder.

Security hardening (#111, slice A7):

- **The original app is retired.** The source-installed app this one replaced has been removed from the repository and gets no further fixes.
- **A Hugging Face token in your Windows environment is no longer used.** To download the speaker model, paste your token in Setup. A token left in your Windows environment is still kept away from the app's other processes.
- **Less left over from the original app.** The speech-model code no longer contains the original installer's own downloader, the network guard no longer has a way to let downloads through in the app's own processes, and error messages point to Repair in Settings > Manage downloads instead of the original app's Update / repair button.
- **Smaller package.** Three packages only the original app used (darkdetect, sv-ttk and tkinterdnd2) are no longer installed.

Security hardening (#111, slice B1):

- **Every package in the app is hash-locked.** The package build installs only the locked set and refuses any file that does not match its pinned SHA-256, and a daily audit checks the locked packages for known vulnerabilities. The installed packages and versions are unchanged.

Security hardening (#111, slice B2):

- **A leaner, precompiled package.** The package leaves out what Unminute never uses: three packages (grpcio, pyannoteai-sdk, setuptools), the test suites inside packages, files only needed to build software, and some binaries for other processors: about 15,000 files, 15 of them programs and libraries. Every module now ships precompiled (about 10,000 files), so Unminute writes nothing into its own folder when it runs. Together these take the zip from about 27,800 files to about 23,000. The precompiled files add about 79 MB, so the zip is about 379 MB, including the cryptography library added in slice C1 (the 0.4.3 zip was 329 MB).
- **The package says what is in it.** It now includes a software bill of materials (`sbom.cdx.json`, also published beside the zip), third-party notices that also list the native libraries each component bundles, a list of every executable file with its SHA-256 and signature details, and a manifest of the pinned model files for checking a copy staged by IT.
- **Reproducible release builds.** Building the same release twice with the same tools gives the same zip, byte for byte. A release is built only from the committed files of its tagged commit, with no local changes, and any new executable file or changed signer stops the build until it is reviewed.

Security hardening (#111, slice B3):

- **Releases are built by GitHub, with signed build provenance.** Each package is built from the tagged code on GitHub's own servers, with a signed record of how it was built and a signed software bill of materials, and is published only after the owner approves it. The zip itself is still not code-signed. A release also has to pass the performance, crash, lifecycle, window and accessibility checks, run against that exact package. IT can check a download before packaging it with `tools/intune/Get-VerifiedRelease.ps1`.
- **The release build no longer fails its signature check when started from PowerShell 7, as on GitHub's runners.** The check that the bundled Python is signed by the Python Software Foundation is as strict as before, and Windows PowerShell now runs only from the Windows system folder, with modules only from the folders an administrator controls.

Security hardening (#111, slice B4):

- **Python 3.14.** The app now runs on CPython 3.14.8. Python 3.12 no longer gets Windows releases with security fixes; 3.14 is planned to get them until October 2027. PyTorch, used for speaker identification, moves from 2.13.0 to 2.14.1, so its graphics card build for Python 3.14 can be checked against the hash PyTorch publishes for it. Other packages keep their versions.
- **No outside debugger.** Python 3.14 lets another program attach a debugger to a running Python program and run code in it. Unminute now starts with that switched off.
- **The graphics card component downloads again.** It is now the build for Python 3.14. If you use it, download "Graphics card acceleration" again in Settings > Manage downloads (about 2 GB) and turn "Use the graphics card" back on. A copy downloaded by version 0.4.3 or earlier stays in that version's model folder until you delete it.

Security hardening (#111, slice B9):

- **The speaker model loads only what was checked.** Each speaker model file is now read once and checked, and speaker identification is built from those same bytes in memory. Before, pyannote opened the files again after the check, and in a way that could run code from a tampered file. The model's weights are now read in a mode that cannot run code. Only the pinned model's exact settings are accepted, and a file that fails is refused with one plain message. `--self-test` checks that a model file built to run code is refused (#218).

Security hardening (#111, slice C1):

- **The package now includes the cryptography library, with its own copy of OpenSSL, ready for encryption at rest.** Nothing uses it yet: a later update encrypts meeting content with it (`docs/ENCRYPTION.md`). IT will see it in the bill of materials, the third-party notices and the binary list.

Security hardening (#111, follow-up to A6):

- **The page can no longer show its own text in a message box.** The browser's built-in alert, confirm and prompt boxes are turned off, and the page's alert no longer opens a Windows message box, so a compromised page cannot pose as the app or as Windows with instructions such as "tick the box, then Allow". The app's own dialogs are unaffected. Page script can still open a file picker or print preview (#175).
- **The page can no longer ask for the microphone or the screen.** Browser permission requests (microphone, camera, notifications and the rest) and screen-capture requests are refused at once, with no browser prompt or picker, so recording only ever starts through the app's own confirmation.

## v0.2.0

A Windows app that transcribes, reviews and cleans up meeting recordings on your own computer. This first full release brings together the four previews (v0.2.0-preview.1 to preview.4).

**Install:** for your Windows account, without administrator rights. It is built for unattended deployment through Intune, which has not yet been tested on a managed device (see Known limitations). An installed preview updates and keeps your workspace.

### What it does

- **Local transcription.** Parakeet v2 is the recommended model. Parakeet v3 and Whisper large-v3 turbo are alternatives. Models are downloaded once in Setup and checked against pinned SHA-256 checksums before use. The checksums match those Hugging Face publishes.
- **Speaker identification (optional).** It uses pyannote community-1 and needs a free Hugging Face token once. You can name, merge and reassign speakers.
- **Review.** A searchable, timestamped transcript with clip playback, autosaved edits and undo.
- **Handoff.** Copy a prompt and the transcript for your own AI assistant, or save Markdown. You see an exact preview first, and you can leave out passages and redact words.
- **Cleanup in two confirmed steps.** The audio is removed once you confirm the transcript is reviewed. The transcript is removed once you confirm the final document is saved elsewhere. Retention holds block cleanup until someone releases them, and they never expire on their own.
- **Watched folders.** These include OneDrive online-only files, which are left alone unless you allow fetching. Deleting originals needs a separate, revocable permission per folder.
- **Microphone recording (optional, off by default).** It saves to disk as it goes. Gaps, a full disk and a disconnected microphone are reported, never hidden, and it never switches device.
- **Privacy.**
  - Processing stays on your computer, and the known telemetry switches of the libraries it uses are forced off.
  - The app blocks its own network connections, except the model downloads you start in Setup. On managed devices, an outbound firewall rule is the stronger control.
  - Cleanup cannot remove copies in synced folders or anything you have shared.
- **Updates and rollback.** An update that changes how the workspace is stored waits until the workspace is empty. You can roll back to the previous version, unless an update has changed how the workspace is stored.
- **Accessibility.** Keyboard access, Ctrl+zoom from 50% to 300%, layouts that reflow at 320 CSS pixels wide (the WCAG test for 400% zoom), and accessible names for screen readers.
- **Resources.** Quiet mode is the default, Faster mode is optional, and on battery automatic work waits by default.

### Known limitations

These have not yet been verified. Details are in docs/RELEASE_CHECKLIST.md and docs/VALIDATION_RUNBOOK.md.

- **Clean profile and Intune.** Not yet tested on a clean standard-user Windows profile, or deployed through Intune on a managed device (#10, #11).
- **No code signing.** This project's installer scripts are not code-signed. Integrity rests on the published `.sha256` and the installer's per-file check. The signing route is still to be chosen (#11).
- **Transcription quality.** Measured on public test clips and synthetic audio only, not on representative business recordings (#12, #25).
- **Accessibility with people.** Not yet tested with a screen reader, Windows contrast themes or nontechnical pilot users (#27).
- **Hardware.** The minimum is 4 processor cores and 8 GB of memory, and 8 cores and 16 GB are recommended. The installer warns below the minimum. Neither level has been tested yet. Testing was on one laptop: an Intel Core Ultra 7 255H with 32 GB of memory, CPU only, on Windows 11 (#28). Windows 10 1809 or later passes the installer's checks but has not been tested.
- **Alternative models.** Parakeet v3 and Whisper large-v3 turbo were tested only in the retired source app's engine, not in the workspace. In that test, Parakeet v3 dropped speech on some clips.
- **Microphone hardware.** Unplugging a USB or Bluetooth microphone mid-recording has not been tested on hardware (#30). Dragging a recording onto the window has not been tested on hardware either; the Import dialog has.
- **No GPU acceleration.** It is not included.

Confirming the final deliverable is saved removes the transcript working content, leaving no removed text readable in the database. Cleanup intent survives crashes and is retried (#17).
- Workspace (in development, not yet in the app): speaker separation runs after transcription as a separate pass that never changes transcript text, keeps overlap evidence and restarts cleanly if interrupted (#16).

The app process also refuses all non-local network access outside deliberate model downloads, so no usage statistics can be sent.
